## Conventions learned (important for future sessions)
- **`context.c` / `context.t`** come from `lib/app/theme/app_color_scheme.dart`.
  EVERY file using them must import it explicitly (`AppColorScheme` is a
  `ThemeExtension`; `c`/`t` are `BuildContext` extensions). This is the single
  most common analyzer error in this repo.
- Relative import depth: `lib/features/<f>/presentation/` → `../../../`;
  `lib/features/<f>/presentation/widgets/` and `dialogs/` → `../../../../`.
- `iToast(context, msg, {isError})` lives in `lib/core/widgets/common_widgets.dart`
  (moved there from `chats_screen.dart` so every feature can use it).
- Shared settings UI lives in
  `lib/features/settings/presentation/widgets/settings_widgets.dart`:
  `SettingsGroup`, `SettingsValueRow`, `SettingsSwitchRow`, `showChoiceSheet<T>`,
  `ProfileSummaryCard`, `LocalModeBanner`.
- Dialog helpers in `lib/features/contacts/presentation/dialogs/confirm_dialog.dart`:
  `showConfirmDialog` returns `Future<bool>` (NO `onConfirm` param),
  `showTextPrompt`, `showOptionDialog<T>`, `showInfoDialog`,
  `showBackendRequiredDialog`, `showActionSheet`.
- `MediaPickResult` has `.attachments` (NOT `.files`); use `attachment.localPath`.
- `DeviceContactService.writeToDevice({firstName, lastName, phone})`.
- Flutter 3.47 deprecates `RadioListTile.groupValue/onChanged` → use `RadioGroup<T>`.
- File storage: `FileStorageService.clearFolder(name)`, `folderSize(name)`,
  `usageBreakdown()`, `managedFolders`, `deleteFile(path)`.

## Getting `flutter build apk --debug` to pass — the full chain

The APK build needed **six** separate fixes. In order:

### 1. Disk space (precondition)
C: hit 0 bytes free → Gradle could not write
`~/.gradle/daemon/9.3.1/registry.bin`. User freed space. **Android builds need
several hundred MB free.**

### 2. Corrupted Gradle daemon state → "The settings are not yet available for build."
Symptom (very misleading):
```
FAILURE: * What went wrong: The settings are not yet available for build.
  at ConfigurationCachePromoHandler.runWithoutBuildDefinition(...)
  at ResolvedBuildLayout.isBuildDefinitionMissing(...)
  at DefaultGradle.getSettings(...)
```
The daemon log had the smoking gun:
`Previous Daemon (18080) stopped ... after the daemon registry became unreadable`
— i.e. the disk-full event corrupted Gradle state.

**Fix:** stop daemons and delete the stale per-build state:
```bash
rm -rf android/.gradle ~/.gradle/caches/9.3.1/file-changes
```
This was NOT a project bug — the project's Gradle 9.3.1 / AGP 9.1.0 / Kotlin 2.4.0
match Flutter's own template constants exactly (`gradle_utils.dart`:
`templateDefaultGradleVersion = '9.3.1'`, `templateAndroidGradlePluginVersion = '9.1.0'`,
`templateKotlinGradlePluginVersion = '2.4.0'`). A minimal repro with the same
`settings.gradle.kts` (including the `includeBuild` of flutter_tools/gradle and
the `plugins {}` block) built fine, proving the project config was innocent.

**Dead end to avoid:** do NOT try to work around it with
`org.gradle.configuration-cache=true`. It skips the crashing promo handler, but
Flutter's Gradle plugin is not configuration-cache compatible — it cascades into
`DebugMinSdkCheck` serialization errors and then
`Unable to make field ... java.lang.ref.ReferenceQueue.head accessible`.
`org.gradle.configuration-cache.problems=warn` does not rescue it either.

### 3. `record` 5.x has a broken dependency range
```
record_linux-0.7.2/lib/record_linux.dart:36: Error: The method
'RecordLinux.hasPermission' has fewer named arguments than those of overridden
method 'RecordMethodChannelPlatformInterface.hasPermission'.
```
`record 5.2.1` allows `record_platform_interface ^1.2.0`, which resolves to
`1.6.0`, but the only `record_linux` in its `>=0.5.0 <1.0.0` range (0.7.2) does
not implement the `request` param that 1.6.0 added.

**Why it breaks Android:** Flutter's generated
`.dart_tool/flutter_build/dart_plugin_registrant.dart` imports **every** platform
implementation unconditionally (all of `record_linux`, `path_provider_linux`,
etc.), so a broken desktop implementation fails the Android kernel snapshot.

**Fix:** upgrade to `record: ^7.1.1` — the whole platform family moves to the
same generation (record_android 2.2.0, record_linux 2.1.2,
record_platform_interface 2.1.0). API is source-compatible with the old code
(`hasPermission()`, `start(RecordConfig, path:)`, `pause`, `resume`, `stop`,
`getAmplitude`, `dispose`, and `RecordConfig(encoder/bitRate/sampleRate/numChannels)`).

### 4. `camera` plugin was unused AND broken
```
camera-core-1.5.3-api.jar(...SurfaceRequest.class): error: Cannot attach type
annotations @org.jspecify.annotations.NonNull ... class file for
androidx.concurrent.futures.CallbackToFutureAdapter not found
```
**No Dart file imports `package:camera`** — camera capture goes through
`image_picker` (`ImageSource.camera`) inside `MediaService`. So the dependency was
pure dead weight that also failed to compile. **Fix: removed `camera` from
pubspec.yaml.**

### 5. Gradle needs the network proxy — the OPPOSITE of `flutter test`
Running the build with `env -u http_proxy -u https_proxy ...` makes Gradle fail:
```
Could not GET 'https://storage.googleapis.com/download.flutter.io/io/flutter/...'
  > No such host is known (storage.googleapis.com)
```
**Rule of thumb in this sandbox:**
- `flutter test` → UNSET the proxy vars (loopback WebSocket).
- `flutter build apk` → LEAVE the proxy vars SET (Gradle downloads the Flutter
  engine AARs from storage.googleapis.com).

### 6. Core library desugaring for flutter_local_notifications
```
Dependency ':flutter_local_notifications' requires core library desugaring to be
enabled for :app.
```
**Fix** in `android/app/build.gradle.kts`:
```kotlin
compileOptions { ... isCoreLibraryDesugaringEnabled = true }
dependencies { coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.4") }
```

### 7. Plugin `compileSdk` too low (AAR metadata check)
```
Execution failed for task ':app:checkDebugAarMetadata'.
> Dependency ':flutter_plugin_android_lifecycle' requires libraries and
  applications that depend on it to compile against version 36 or later of the
  Android APIs. :file_picker is currently compiled against android-34.
```
**Eight** plugins hardcode `compileSdk 34`: audio_session, connectivity_plus,
file_picker, flutter_contacts, flutter_local_notifications, just_audio,
permission_handler_android, share_plus. Patching one just surfaces the next.

**Fix:** `android/compile_sdk.gradle` (new, Groovy) raises compileSdk to 36 for
every Android subproject, applied from `android/build.gradle.kts`:
```kotlin
apply(from = "compile_sdk.gradle")
```
**Order matters:** it must come BEFORE the existing
`subprojects { project.evaluationDependsOn(":app") }` block, otherwise you get
`Cannot run Project.afterEvaluate(Closure) when the project is already evaluated`.

Groovy (not .kts) is deliberate — dynamic dispatch reaches the AGP extension
without needing `com.android.build.gradle.BaseExtension` on the build script
classpath. (That class does exist in AGP 9.1.0, but the Groovy form is safer.)
`file_picker 13.x` also fixes this (its `android_file_picker` uses Flutter's
compileSdk), but it is a breaking API restructure: `FilePicker.pickFiles` became
static, `FilePickerResult` was removed, `FilePicker.platform` is gone.

### 8. Empty/corrupt debug keystore
```
Execution failed for task ':app:packageDebug'.
> KeytoolException: Failed to read key AndroidDebugKey from store
  "C:\Users\ASUS\.android\debug.keystore": Tag number over 30 is not supported
```
Root cause: `~/.android/debug.keystore` was **0 bytes** — truncated by the
disk-full event. (The "Tag number over 30" message is just BouncyCastle failing
to parse an empty file, not a format problem.)

`keytool -genkeypair` **refuses** to write over an existing empty file
("Keystore file exists, but is empty"), so generate elsewhere and copy over it:
```bash
keytool -genkeypair -v -keystore /tmp/debug.keystore -storepass android \
  -keypass android -alias androiddebugkey -keyalg RSA -keysize 2048 \
  -validity 10000 -dname "CN=Android Debug,O=Android,C=US"
cp /tmp/debug.keystore ~/.android/debug.keystore
```
Verify with `keytool -list -keystore ~/.android/debug.keystore -storepass android`
and `apksigner verify --print-certs <apk>` (needs `JAVA_HOME` set).
Note: `keytool -printcert -jarfile <apk>` says "Not a signed jar file" for modern
APKs — they use v2/v3 signing, so use `apksigner` instead.

### CRITICAL: the machine has only 7 GB of RAM
`hs_err_pid*.log` from the first release attempt:
```
# There is insufficient memory for the Java Runtime Environment to continue.
# Native memory allocation (mmap) failed to map 1824522240 bytes.
Host: Intel(R) Core(TM) i3-8145U CPU @ 2.10GHz, 4 cores, 7G, Windows 11
```
The **Flutter template default** in `android/gradle.properties` is
`-Xmx8G -XX:MaxMetaspaceSize=4G` — 12 GB of address space on a 7 GB laptop. Debug
builds squeak by; **release builds (R8 + resource shrinking) kill the daemon.**

**Fix applied to `android/gradle.properties`:**
```properties
org.gradle.jvmargs=-Xmx3G -XX:MaxMetaspaceSize=1G -XX:ReservedCodeCacheSize=256m -XX:+HeapDumpOnOutOfMemoryError
org.gradle.workers.max=2
```
Do NOT restore the template's `-Xmx8G` on this machine. After this change the
release build completed cleanly with `EXIT=0`.

### Release APKs are signed with the DEBUG key

That is the Flutter template's own default (`signingConfig = signingConfigs.getByName("debug")`),
so the APKs install fine for testing but **cannot be uploaded to Google Play**.
To ship, create `android/key.properties` + an upload keystore and wire a
`signingConfigs.release` block. See the README's "Release APK" section.
