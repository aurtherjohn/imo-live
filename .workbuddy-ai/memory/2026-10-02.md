### ⚠️ The tap/double-tap race — the bug to not reintroduce
Setting **both** `onTap` and `onDoubleTapDown` makes Flutter fire `onTap` on the
first tap of a double-tap, so every seek also toggled the chrome. Fixed with
`onTapUp` + a `kDoubleTapTimeout` timer that the double-tap cancels. The
`onDoubleTap` handler must stay **absent** or it re-breaks.

### ⚠️ Two genuinely dead features found and fixed
1. **`Attachment.thumbnailPath` was read by the bubble and written by nothing.**
   Every video rendered the grey movie-icon placeholder. Fixed by adding
   `lib/core/services/video_thumbnailer.dart` — mounts a real `VideoPlayer` in an
   off-screen `RepaintBoundary` via the root `Overlay`, seeks to 600 ms (frame 0
   is usually a black fade-in), then `RenderRepaintBoundary.toImage()` → PNG via
   `FileStorageService.writeBytes`. **No new plugin**, because a native module
   would change the APK's native lib set.
   ⚠️ First attempt tried to fake a `ui.Image` from the texture id — **impossible
   from pure Dart**; a texture cannot be read back. Deleted it. The
   `RepaintBoundary` route is the only one that works.
2. **`durationMs` was never set either** → the bubble's duration chip was dead.
   Added `MediaFileHelper.videoDurationMs` (opens the container with
   `video_player`, reads the header duration, disposes; returns `null` not `0`).

Both are wired in `MediaService.pickVideo` + `MessageComposer._deliverVideo`.
`Attachment.copyWith` added (it had none).

WCAG AA needs 4.5:1 for body text. Measured **on `#FFFFFF`**:

### Fix
- `AppColorScheme` gained `onSuccess/onWarning/onInfo/onDanger/online`
  (+ light constants in `app_tokens.dart`: `#0E7A3F #8A5A00 #0B6BCB #C42B22`).
  **Dark keeps the raw brand hues** — they already pass; do not "fix" them.
- **Light `accent` = `AppColors.accentDark` `#D6193E`**, NOT brand `#FF2D55`.
  It is the only token that works both ways: 5.16:1 as text on white *and*
  5.16:1 as white-on-accent for a fill.
- **Rule: `context.c.onX` for FOREGROUNDS, raw `AppColors.X` only for FILLS.**
  104 sites migrated / 44 files. 12 raw uses remain, all verified fills/tints.
- Typography: 23 sites within 0.5px of a scale token snapped onto it.
  On-scale 72→94, distinct values 30→25. Left `44/46` (hero), `9/9.5/10`
  (tiny badges), and the ±1 band alone — all deliberate.
- 8 unlabeled `IconButton`s got `tooltip` via `context.l10n` (+4 ARB keys
  `playVideo/pauseVideo/rewind10/forward10`, EN+BN, and a `label` field on
  `_ChromeButton` in `video_view.dart`).

### ⚠️⚠️ TRAPS HIT — a mechanical colour migration fails THREE ways
My substitution script was wrong in three distinct, silent ways. Check all
three after any similar sweep:
1. **Duplicated ternaries.** `x ? a : AppColors.b` → `x ? a : x ? a : context.c.b`.
   Found 5: `calls_screen:542`, `contact_info_screen:568`,
   `message_bubble_parts:183`, `earn_screen:569`, `gift_sheet:230`.
   **Sweep for `<cond> ? <a> : <same cond> ?`** — the analyzer does NOT catch it.
2. **`const` contexts.** A runtime value inside `const Icon(...)` /
   `const TextStyle(...)` / `const BoxDecoration(...)` is an `invalid_constant`
   error. Stripped 41 `const`s by walking up to the innermost enclosing
   constructor. ⚠️ **`prefer_const_constructors` is NOT enabled**, so nothing
   warns if you strip one too many.
3. **Context-free getters.** `AttachmentKind.color` in `attachment_sheet.dart`
   is a `switch` getter with **no `BuildContext`** — `context.c.x` there is
   `undefined_identifier`. Reverted to a literal fill.

Also: 9 files used `context.c.*` without importing `app_color_scheme.dart`
(the 18th error class). And my own **snap script damaged the scale definition**
— `bodyMedium` 14.5 → 14, making it a duplicate of `labelSmall`/`titleSmall`.
Caught by reading the file; **always eyeball the theme file after a bulk edit.**

### Tooling trap
**`python - <<'PY'` heredocs mangle regex backslashes** (`\s`, `+` eaten) —
a scan silently returned "0 sites" twice while grep found 135. **Write the
script to a file, then run it.** Cost me two wasted round-trips.

## Phase 9 — clean / pub get / analyze / test / release build — DONE

### ⚠️⚠️ `flutter clean` COSTS SPACE ON THIS HOST — do not run it "to make room"
Interrupted it after 5 min. `build/` went 2.6 GB → 294 MB **on disk**, but free
space went **5.9 → 4.71 GB**. Every delete routes to the Recycle Bin on `C:`, so
a clean moves bytes into the Bin and frees nothing while destroying the
incremental cache. The skill said so; it is true. `windows-disk-reclaim` again.

### The reclaim that worked (4.26 GiB in seconds)
The Bin held **21,206 files / 4.27 GiB of this project's own build output**
(`.so`, `.apk`, `.dill`) — the interrupted clean plus earlier builds.
`S-1-5-18` (SYSTEM's bin) raises **WinError 5**; only iterate `S-1-5-21-*` SIDs.
Parse each `$I` record: 4-byte path length at **offset 24**, then UTF-16LE path;
truncate the matching `$R` payload only when its original path is under the
project, and skip `st_nlink > 1`. **7385 payloads truncated → 4.70 → 8.97 GB.**
Reclaimed enough to build (a split-per-abi release needs ~5.6 GiB transient).
⚠️ Watchdog must be started with an **absolute** path — `~` does not expand inside
a quoted argument, and it failed silently once.
