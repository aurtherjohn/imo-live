# 2026-09-22 — Imo LIVE: black-screen startup fix + proactive bug hunt

## The reported bug
Debug APK on a physical phone opened to a **permanently black screen** — no crash,
no UI. Root cause found immediately:

```dart
// lib/main.dart (before)
void main() => runApp(const SizedBox());
```

The entry point was a **stub**. Everything else in `lib/` was complete and
analyzer-clean (105 Dart files); `main.dart` had been reduced to a placeholder,
so the app booted a 0-size widget and rendered nothing. Nothing was wrong with
the router, theme, or screens.

**Lesson for future sessions:** when the symptom is "opens but never renders,
no crash", check `main.dart` FIRST. A `SizedBox`/`Container` at the root of
`runApp` is the single cheapest explanation.

## PART 1 — startup hardening (all landed)
`lib/main.dart` rewritten:
- `WidgetsFlutterBinding.ensureInitialized()` before any async work.
- `runZonedGuarded` around binding init + `runApp` (catches pre-first-frame throws).
- Global `ErrorWidget.builder` → self-contained `_StartupErrorWidget` that uses
  **no** theme extensions, providers, or l10n (any of those may be the failure).
  Critical because the app's background is near-black: the stock
  red-on-grey error box reads as a black screen.
- `FlutterError.onError` + `PlatformDispatcher.instance.onError` log the exact
  error to the console for `flutter run`.
- Opens storage **before** `runApp`, then passes the result in via
  `storageReadyProvider.overrideWithValue(storageReady)`.

`lib/local/database/local_database.dart` made resilient:
- Per-box `_openBox(name, allowRecovery:)`; a failure deletes + retries once
  (partially-written `.hive` file is the usual cause), then degrades.
- Added `isDegraded` / `unavailableBoxes` / `retryUnavailable()` / `maybeBox()`.
- **All read/write primitives now go through `maybeBox`** — reads return
  empty/null and writes no-op instead of throwing `StateError`.
- `readList` decodes **per entry**; one malformed record is skipped and logged
  instead of blanking the whole collection.

`lib/features/misc/presentation/startup.dart`:
- `StartupService.run()` wraps every step (demo seed, settings cache,
  notifications) in `_guard`, so one failure can't abort startup.
- **`bootstrapProvider` had a real latent bug**: `stage()` mutated
  `startupStageProvider` *synchronously* during the provider's own build, which
  tripped Riverpod's `_debugCurrentlyBuildingElement` assertion:
  *"Providers are not allowed to modify other providers during their
  initialization."* Fixed with a leading `await Future<void>.delayed(Duration.zero)`.
- Added `startupFailedProvider`; `finally` sets `startupCompleteProvider = true`.

`lib/features/misc/presentation/splash_screen.dart`:
- `.timeout(const Duration(seconds: 10))` on the bootstrap future, catches
  `TimeoutException`, and **always** `context.go(AppRoutes.chats)`. This is the
  last line of defence against a permanently black splash.

## PART 2 — bugs found by audit and fixed
1. **Crash** `language_screen.dart` — `ref.watch(selfProfileProvider).valueOrNull!`
   force-unwrapped three times in one expression; null while loading → crash on
   Settings → Language. Now reads the profile **once** into a local.
2. **Crash (narrow)** `notification_service.dart` — `cancel`/`cancelAll` had no
   try/catch and threw if the plugin was detached. Now guarded.
3. **Silent failure** `notification_service.dart` — `POST_NOTIFICATIONS` was
   declared in the manifest but **never requested**, so on Android 13+ every
   notification was silently dropped. Added `requestNotificationsPermission()`
   in `init()`; exposed `isInitialized`.
4. **Silent failure** `media_service.dart` — `pickImages(fromCamera: true)` only
   returned an error for `permanentlyDenied`; a **plain denial** fell through to
   the picker, returned nothing, and produced a dead button. Now `!result.isGranted`.
5. **Silent failure** `file_service.dart` — same inverted guard in `pickAudio`.
   Introduced `FilePickResult{attachments, error, permissionDenied}` so a refusal
   can be explained; `pickDocuments` kept its `List<Attachment>` signature.
6. **Dead code** `permission_service.openSettings()` was never called. Composer
   now shows a SnackBar with a **Settings** action on `permissionDenied`.
7. **Data loss** `chat_screen.dart` — GoRouter defaults a missing param to `''`.
   Sending with an empty chat id persisted messages under a chat row that does
   not exist → permanently invisible. Added `_hasValidChatId`, refuse to send
   with a toast, and hide the composer entirely.
8. **Visual glitch** `chat_screen.dart` — edit flow called `repo.edit(...)` and
   then `save(_editing!.copyWith(isEdited: true))`, writing the **stale body**
   back over the edit. Removed the second write (`edit()` already sets `isEdited`).
9. **Logic** unread counts — `ChatsNotifier.touch(incrementUnread: true)` was
   never called from anywhere, so nothing ever raised a badge. Added
   `ChatsNotifier.receive(chatId, message)` which updates the preview/timestamp
   and increments (skipping muted chats). `markRead` on open already reset it.
10. **Logic** `local_chat_repository.updateLastMessage` stored
    `lastMessageStatus: message.status.name` even for **incoming** messages, so
    the chat list showed a stale delivery tick. Now `null` when not outgoing.
11. **Fragile** `group_info_screen.dart` — `if (member != group.members.last)`
    compared object **identity** for the divider. Now index-based.
12. **Fragile** `local_database.readList` — `whereType<Map<String,dynamic>>()`
    silently dropped `Map<String,Object?>`; replaced with `Map.from` + per-entry
    try/catch.

### UI overflow fixed (verified at 320dp / 1.6× text scale)
- `calls_screen.dart` `_Tile` — "Favourites" wrapped to 2 lines and overflowed;
  added `maxLines: 2` + ellipsis.
- `message_bubbles.dart` `VoiceBody` — fixed `SizedBox(width: 228)` → 
  `ConstrainedBox(maxWidth: 228)` + `Flexible` + ellipsised time.
- `status_view_screen.dart` `_buildFooter` — both labels wrapped in `Flexible`.
- `chats_screen.dart` `_TopBar` — fixed 58dp height → scales with
  `MediaQuery.textScalerOf(context).scale(1)`.
- Confirmed **clean**: `chat_tile.dart`, composer `_InputRow` (already
  `Expanded`-guarded), poll body, all `.when`/`orEmpty`/`firstOrNull` screens.

## PART 3 — verification
- `flutter analyze lib/` → **No issues found!**
- `flutter test` → **All 66 tests passed** (55 pre-existing + 11 new)
- New file `test/startup/startup_regression_test.dart` (11 tests) pins:
  entry point is not a stub (reads `lib/main.dart` source and asserts
  `runApp(`, `ensureInitialized`, `ProviderScope`, `ErrorWidget.builder`
  present and `runApp(const SizedBox())` **absent**); `bootstrapProvider`
  completes with no storage; DB primitives safe before `init()`; `readList`
  skips malformed records; incoming message increments unread + null tick;
  `markRead` zeroes the badge; `edit()` sets `isEdited`; `FilePickResult`
  semantics; a build failure renders an `ErrorWidget`.

### Test-writing gotchas hit
- `readList` gates on `LocalDatabase`'s **internal open-box set**, not raw
  `Hive.isBoxOpen`. A test must call `init()` first, then write to a real box.
- `ErrorWidget.builder` must be restored **inside the test body** — the binding
  asserts it is unset when the body returns; `addTearDown` is too late.
- `takeException()` is needed or the simulated build failure fails the run.
- `Chat.fromJson` is fully tolerant, so it never throws on missing keys; to
  exercise the skip path you need a **type** mismatch (e.g. `id` as an object).

- **No device or emulator is attached** (`adb devices` empty, no AVDs), so
  on-device `flutter run` verification was not possible from this session.
- Proxy rule unchanged: `flutter test` → **unset** proxy vars;
  `flutter build apk` → **leave them set**.
