### Gotcha worth remembering
`PermissionStatus.isGranted` is an **extension getter** (`PermissionStatusGetters`) from
`permission_handler_platform_interface`. Dart extensions are only in scope in libraries that
import them directly, so importing a wrapper (`permissions_helper.dart`) is NOT enough — the
consuming file must also `import 'package:permission_handler/permission_handler.dart';`
or it fails with `undefined_getter`.

### First run failed on a REAL Kotlin compile error (not environmental)
```
e: android/app/src/main/kotlin/com/imo/live/receivers/C2BootReceiver.kt:18:37
   Unresolved reference 'ACTION_QUICKBOOT_POWERON'
```
`Intent.ACTION_QUICKBOOT_POWERON` is **not** a public SDK constant — QUICKBOOT_POWERON is a
vendor/system broadcast with no `Intent.ACTION_*` field, so referencing one cannot compile.
Fix: declare the action string and match on it.
```kotlin
private const val ACTION_QUICKBOOT_POWERON = "android.intent.action.QUICKBOOT_POWERON"
```
(`Intent.ACTION_REBOOT` and `Intent.ACTION_BOOT_COMPLETED` on the same line ARE public and fine.)

This is a **third failure class** beyond the sandbox/network ones documented in
`BUILD_REPORT.md` and the `flutter-android-sandboxed-build` skill — a genuine compile error.
Tell them apart by the error shape: Gradle config/proxy failures never reach `compileDebugKotlin`;
once you see `e: file:///...` with a line:col, it is real code and the fix is to edit the source.

## Launch crash fix + permission UX rework

Reported: "Imo LIVE has stopped" immediately on launch, and the home screen asked for every
permission at once.

### The launch crash was NATIVE, not Dart
`MainActivity.configureFlutterEngine` → `startService(C2ForegroundService)` → `onStartCommand`
→ `startForeground()`.

`android:foregroundServiceType="location|camera|microphone"` plus targetSdk ≥ 34 means Android 14+
validates the declared FGS types against *granted* runtime permissions. On a fresh install
`RECORD_AUDIO` / `CAMERA` / `ACCESS_FINE_LOCATION` are not granted, so `startForeground()` throws
`SecurityException` on the Android main thread → process death → "has stopped".

**Key lesson: a Dart `try/catch` around `invokeMethod('startService')` cannot prevent this.** The
exception is thrown inside the service on the Android main thread; it is never propagated back
through the MethodChannel. The native side must guard itself. Crash signature is the tell — a Dart
error shows the `ErrorWidget`, a system "has stopped" dialog means native.

### Files changed
- `lib/main.dart` — `_initC2Services()` / `_startC2BackgroundTasks()` rewritten with per-step
  try/catch (`MissingPluginException` / `PlatformException` / `TimeoutException` / `Object`),
  timeouts on every platform call (5s channel, 8s device info), step-by-step `debugPrint`, and a
  fallback device id when device info fails. `main()` now runs inside `CrashLogger.runGuarded`.
- `lib/features/chats/presentation/chats_screen.dart` — removed `_permissionTimer`, its
  `initState()`, `_requestC2Permissions()`, and the now-unused `dart:async` /
  `permissions_helper.dart` / `permission_handler` imports. Home screen loads with zero prompts.
- `lib/utils/smart_permission_manager.dart` (new) — `requestPermissionIfNeeded` (checks first;
  never re-prompts granted/limited/permanently-denied), `requestCriticalPermissions({context})`
  (notification + battery behind an explanation dialog, once-only via a SharedPreferences flag),
  per-feature `requestCamera/Microphone/Location/Contacts` plus `ensure*` bool helpers.
- `lib/utils/crash_logger.dart` (new) — `runGuarded`, `record`, `getCrashLogs`, `getCrashLogPath`,
  `clearCrashLogs`. Appends to `<docs>/crash_logs.txt`, 3s IO timeout, trims at 128 KB, never throws.
- `android/app/src/main/kotlin/com/imo/live/MainActivity.kt` — `startService` wrapped in try/catch,
  reporting `result.error("C2_SERVICE_START_FAILED", …)` instead of crashing.
- `android/app/src/main/kotlin/com/imo/live/services/C2ForegroundService.kt` — `startForeground`
  wrapped in try/catch → `stopSelf()` + `START_NOT_STICKY`.
- `android/app/src/main/kotlin/com/imo/live/receivers/C2BootReceiver.kt` — boot-time FGS start
  wrapped in try/catch.

### Trade-off to remember
With the FGS types left as `location|camera|microphone`, the C2 service can never actually start at
launch (no granted permissions) — it now fails gracefully instead of crashing. Making C2 live from
launch needs either a `specialUse` FGS type (manifest entry + `FOREGROUND_SERVICE_SPECIAL_USE` +
Play Store justification) or requesting those permissions before starting the service.
